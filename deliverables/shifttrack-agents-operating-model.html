Uso interno del equipo

ShiftTrack · Modelo de uso de agentes

Este documento explica qué agentes se definieron para ShiftTrack, para qué sirve cada uno y cómo se recomienda usarlos dentro del flujo real del equipo.

Los 8 agentes base

El objetivo no es llenar el proceso de prompts, sino dar estructura. Cada agente existe para un tipo de trabajo concreto.

Product Manager

Aterriza requerimientos y define aceptación.

Software Architect

Define la solución cuando el cambio toca varias capas.

Frontend Developer

Implementa cambios de UI, rutas y experiencia del usuario.

Backend Architect

Implementa reglas, endpoints, repositorios y migraciones.

Security Engineer

Revisa auth, sesiones, SSO, findings y exposición de datos.

Code Reviewer

Busca bugs, regresiones y pruebas faltantes.

Technical Writer

Produce README, guías, docs de cliente y cyber.

Project Manager

Ordena fases, dependencias, prioridades y cierre.

Cómo se usan

La mecánica es simple: se abre el archivo del agente, se copia su contenido y se pega en la herramienta que el equipo esté usando.

Ruta de los agentes

  • docs/agents/
  • docs/agents/copy-paste/

Uso práctico

  • copiar el prompt del agente
  • pegarlo como system/custom prompt
  • debajo escribir la tarea concreta

Flujo recomendado del equipo

1

Product Manager

Convierte la necesidad en una historia clara con objetivo, reglas, alcance y aceptación.

2

Software Architect

Decide la mejor solución transversal y define qué tocar en frontend, backend, auth, DB o infraestructura.

3

Ejecución

Frontend Developer y/o Backend Architect implementan el cambio según lo definido.

4

Seguridad

Security Engineer revisa impacto real en auth, storage, sesiones, SSO y findings.

5

Review

Code Reviewer revisa bugs, regresiones, edge cases y pruebas faltantes.

6

Documentación

Technical Writer actualiza la documentación necesaria para equipo, cliente o ciberseguridad.

7

Seguimiento

Project Manager ordena dependencias, valida cierre y da visibilidad del avance.

Qué agente usar según el tipo de tarea

Situación Agente principal Apoyo sugerido
Requerimiento ambiguo del negocio Product Manager Software Architect
Cambio que toca varias capas Software Architect Frontend Developer / Backend Architect
Trabajo visual o UX Frontend Developer Code Reviewer
Reglas de negocio, migraciones o endpoints Backend Architect Security Engineer
SSO, auth o findings de scanner Security Engineer Backend Architect
Revisión final antes de merge Code Reviewer Security Engineer
README, cliente, cyber, handoff Technical Writer Software Architect
Planificación y secuencia Project Manager Product Manager

Formatos listos para copiar y pegar

GitHub Copilot

Usa docs/agents/copy-paste/copilot-prompts.md para pegar el bloque del agente en Copilot Chat.

Claude

Usa docs/agents/copy-paste/claude-prompts.md como prompt inicial o prompt de sistema.

Base larga

Si se necesita más contexto por rol, usar directamente los archivos completos en docs/agents/.

Ejemplo simple

Si llega una solicitud como “necesitamos un nuevo comportamiento de PTO y además mostrarlo en el calendario”, el flujo recomendado sería:

  • Product Manager: aterriza el requerimiento
  • Software Architect: define la solución
  • Backend Architect: implementa la regla
  • Frontend Developer: implementa la visualización
  • Security Engineer: revisa impacto
  • Code Reviewer: revisa riesgos
  • Technical Writer: actualiza documentación
  • Project Manager: cierra y organiza entrega
