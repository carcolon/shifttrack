1. Vision general

Que es ShiftTrack

ShiftTrack es una plataforma web para gestionar horarios operativos, coverage semanal, PTO, Day Off, change requests, administracion de empleados y revisiones por jerarquia.

Shift CalendarEmployeesRequestsPTODay OffSwapsCoverageSSO Entra ID

Arquitectura de alto nivel

  • Frontend: React 19 + TypeScript + Vite.
  • Backend: ASP.NET Core 8 + Dapper + SQL Server.
  • Realtime: SignalR.
  • Motion: GSAP y Motion.
  • Auth: cookie HTTP + CSRF + Entra ID con PKCE.
  • Datos: migraciones SQL aplicadas al iniciar la API.

Estructura general del repositorio

Auth, Entra ID, GSAP y SignalR en frontend

  • La sesion principal se rehidrata via /auth/me.
  • No se persisten bearer tokens sensibles en sessionStorage.
  • Entra ID usa PKCE con state, code_verifier y code_challenge.
  • GSAP vive en ShiftTrackLoader.tsx, Modals.tsx, DashboardAmbientBackground.tsx, ShiftCalendarPage.tsx, DashboardPage.tsx y MaintenancePage.tsx.
  • SignalR vive en src/lib/signalr.ts y se usa principalmente desde calendario/dashboard.
  • vite.config.ts separa chunks para React, Router, GSAP y SignalR.

Seguridad, SignalR y SSO en backend

  • JWT y cookie auth soportados por ASP.NET Core 8.
  • CSRF token expuesto para requests sensibles.
  • SSO con Entra ID por Authorization Code + PKCE.
  • SignalR registrado en ServiceCollectionExtensions.cs y servido por ScheduleHub.cs.
  • La API comparte auth con SignalR para conexiones autenticadas.
  • Azure Key Vault y Azure Identity estan soportados por configuracion.

4. Reglas de negocio actuales

Roles

RolComportamiento
AdminControl total. Autoaprueba PTO y Day Off.
ManagerGestion amplia. Sus PTO/Day Off requieren aprobacion de admin.
Team LeaderComo Employee, pero puede ver coverage.
EmployeeConsulta su horario y solicita PTO / Day Off / swaps para si mismo.

Modulos funcionales

  • Calendario semanal con coverage, holidays, PTO y Day Off.
  • Vista anual navegable por ano.
  • PTO, Day Off y Change Request desde el mismo modal.
  • Requests con tabs separadas para PTO, Day Off y Swaps.
  • Employees, export, review pages y realtime.

PTO

  • Employees y Team Leaders no pueden pedir PTO en pasado ni a mas de 60 dias.
  • Vacation cuenta solo dias habiles: lunes a viernes no festivos.
  • Sabados, domingos y holidays dentro del rango de vacation se pintan, pero no descuentan dias.

Day Off Request

  • Aparece en el popup junto a PTO y Change Request.
  • Aparece en Requests como familia separada.
  • Admin puede montarselo a si mismo o a otros y queda autoaprobado.
  • Manager puede pedirlo para si o para otros, con aprobacion de admin.
  • Employee y Team Leader solo pueden pedirlo para si mismos, con aprobacion de managers o admins.
  • No se permite pedir Day Off en una fecha que ya es Day Off.

Coverage, holidays y correos

  • Coverage se calcula con thresholds distintos por dia de la semana.
  • Admin recibe warning antes de guardar o aprobar PTO / Day Off si se afecta coverage.
  • El warning actual muestra fecha, agentes activos proyectados, coverage proyectado y minimo requerido.
  • La app sirve holidays de Colombia por ano o por rango desde /holidays.
  • Si un agente trabaja en holiday, la letra del turno se pinta en rojo.
  • Los correos de PTO y Day Off incluyen comentarios; si no hay comentario, muestran N/A.
  • Jerarquia de correo: Employee / Team Leader notifican a Managers y Admins; Manager notifica a Admins; Admin se autoaprueba.

5. Flujo funcional completo

  1. El usuario entra por login local o Entra ID.
  2. La app rehidrata sesion con /auth/me.
  3. El dashboard dirige a /app/calendar, /app/employees o /app/requests.
  4. El calendario carga semana, holidays, coverage y filas de empleados.
  5. Desde el calendario se puede crear PTO, Day Off o Change Request.
  6. Si la accion requiere aprobacion, la API crea la request y dispara correo a reviewers segun jerarquia.
  7. Reviewers aprueban o niegan desde Requests o review pages dedicadas.
  8. Al aprobar o negar, se actualizan requests, schedule overrides, correos y realtime via SignalR.
