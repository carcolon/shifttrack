ShiftTrack Assistant Rules Inventory
===================================

Scope
-----
This file tracks the rules-based queries supported by Tracky in ShiftTrack.
The assistant is deterministic: it normalizes the text, detects patterns,
resolves dates and week context, and then queries the real schedule data.

Normalization Rules
-------------------
- Not case-sensitive.
- Not accent-sensitive.
- `mañana` and `manana` are treated as the same token.
- Tolerates extra punctuation in common questions.
- Works in English and Spanish.
- Employee lookup supports:
  - first name
  - first name + last name
  - exact email

Examples of equivalent inputs:
- "DIAS LIBRES DE JHON DOE"
- "dias libres de jhon doe"
- "quien trabaja en el turno de la mañana"
- "quien trabaja en el turno de la manana"
- "Days Off of Jhon Doe"
- "days off of jhon.doe@company.com"

Matching Behavior
-----------------
- If a single-token name matches multiple employees, Tracky returns all matches.
- If an exact email is provided, Tracky uses it as the primary identifier.
- For day-specific questions, Tracky filters the answer to that exact day.
- For week-wide questions, Tracky returns the matching facts across the selected or requested week.
- It also supports natural filters for:
  - operation / operacion: `leaders`, `outbound`, `referral`, `esq`, `sgf`
  - company / empresa / compania: `solvo global`, `sgf`
  - location / ubicacion / sede: `col`, `arg`, `wpb`
  - role / rol / for / para: `manager`, `admin`, `employee`, `gerente`, `administrador`, `empleado`
  - shift / turno: `morning`, `late`, `mañana`, `manana`, `tarde`

Current Limitations
-------------------
- Tracky is still rule-based, not a generative model.
- It does not support arbitrary free-form conversation outside the rule sets above.
- Ambiguous slash dates are interpreted as day/month/year.
- Multi-intent prompts in one sentence may still fail if they mix unrelated requests.
- It does not yet answer analytical questions such as totals, averages, trends, or comparisons.
- It still depends on explicit rule patterns, even though the coverage is broad.

Recommended User Guidance
-------------------------
- For week queries, prefer "this week", "next week", "last week", or "week of YYYY-MM-DD".
- For exact dates, prefer ISO or full natural dates.
- For employee-specific queries, use full name or email if there are duplicates.
- For day-specific checks, include the weekday or exact date explicitly.
